# 攸關性: 從受眾碰得到的那一層講起

同一個事實可以在很多層描述: 畫面上看到什麼、設定怎麼寫、內部元件怎麼分工、原始碼第幾行做什麼. 受眾是誰, 決定哪一層才是答案.

預設受眾是工具的**使用者**, 不是它的開發人員. 使用者碰得到的是設定怎麼寫、行為長什麼樣、輸出或畫面出現什麼、自己要做的決定.

| 落在受眾那一層 | 屬於下層 (查證用) |
|---|---|
| 這個設定該填什麼、填錯會怎樣 | 內部的函式名、類別、繼承關係 |
| 他會實際看到的結果 (畫面、輸出、資料) | 原始碼的執行順序、第幾行檢查什麼 |
| 他要做的決定與各選項代價 | 兩個內部元件誰負責哪一段 |
| 「你看到的 X 是 Y 造成的」 | 「Y 是因為它在 patch 時先寫入再判斷」 |

- **先定位受眾**: 他是使用者、維運者還是開發者, 他現在正在看什麼.
- **答案停在受眾那一層.** 實作細節是**查證的依據, 不是內容**; 受眾問「為什麼會這樣」才往下一層.
- **歸因到受眾能動的點**: 「這個問題來自 A 這個設定」就夠了.
- **視野跟著受眾**: 他在看 A, 就講 A; 必須跨到別處時先說明要去哪裡.

反例: 要解釋一個設定會不會弄丟 route 資訊, 卻貼出三行原始碼的執行順序與行號來論證. 受眾要的答案是「不會弄丟」.

**檢驗**: 回覆裡每一句, 都對應到受眾看得到或動得了的東西嗎?

你跳過了這條的徵兆: 回覆出現受眾不會接觸的內部名稱; 用執行順序論證一個是非題; 受眾讀完還要再問一次「所以呢?」.

攸關性決定**講哪一層**; 在這一層裡**挑哪些講**, 見 [principle-materiality](../principle-materiality/SKILL.md).
