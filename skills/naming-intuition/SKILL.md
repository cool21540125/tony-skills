# Naming Intuition

使用者母語是中文. 目標不是給字典翻譯, 而是讓他「用英文的腦」感受這個名字: 母語者看到這個字時腦中浮現什麼畫面, 為什麼這個畫面剛好對應到這個功能.

## 回答結構

依序回答, 每段都要短. 不需要的段落直接省略, 不要硬湊.

1. **一句話結論**: 這個名字在說什麼畫面 + 對應到什麼行為.
   例: `clamp_min` = 「用夾鉗把值的下緣夾住」→ 低於 min 的值一律變成 min.
2. **英文單字本身**
   - 本義與具體意象 (優先講實體物件或動作, 例: clamp 是木工的 C 型夾鉗).
   - 母語者日常怎麼用這個字 (1-2 個自然例句, 附中文).
   - 詞性與搭配: 是動詞還是名詞、常見 collocation (例: clamp down on).
   - 字源只在有助理解時才講 (例: 拉丁字根能串起一族字).
3. **為什麼這樣命名 (典故 / 傳統)**
   - 這個字在該領域或更早的領域是否已有慣例 (例: clamp 來自 GLSL / shader、C++ `std::clamp`、數學與圖學的 saturate 傳統).
   - 作者或團隊選這個字的用意; 有官方文件、設計文件、PR、issue、commit message、作者訪談佐證就引用.
   - 命名中的其他部件也拆開 (例: `_min` 是「夾哪一邊」, 不是「取最小值」).
4. **近義候選字對照表**: 為什麼不用別的字. 用表格:

   | 候選字 | 母語者的感覺 | 為何不選 / 差在哪 |
   |---|---|---|

5. **中文翻譯的陷阱**: 常見中譯若會誤導就點出 (例: `clamp_min` 直覺讀成「取最小」, 實際行為接近 `max(x, min)`, 方向正好相反).
6. **記憶鉤子** (選用): 一句話或一個畫面幫助記住.

## 求證紀律

- 典故與命名用意是最容易編造的部分. 只有查到出處 (官方文件、原始碼註解、PR / issue / mailing list、作者發言) 才能寫成事實, 並簡述出處是什麼.
- 查不到時寫「未查證」並明說以下是基於英文語感與領域慣例的推論, 不要包裝成典故.
- 查證手段: 用可用的網路搜尋 / 抓取網頁工具, 先查官方文件與 GitHub repo (PR, issue, commit 歷史). 沒有網路工具時, 典故一律標「未查證」.
- 單字本義與日常用法屬語言常識, 不需另外查證.

## 風格

- 先畫面後定義: 先讓使用者「看到」這個字, 再講技術行為.
- 不講該功能的完整用法教學; 使用者想學用法會另外問.
- 若名字本身取得不好 (母語者也覺得彆扭、有歷史包袱、或社群有爭議), 直接說, 這也是語感的一部分.

## 範例

輸入: `prometheus 的 clamp_min`

輸出骨架:

> **結論**: clamp = 夾鉗. `clamp_min(v, 0)` = 把數值的「下限」夾住在 0, 低於 0 的被抬到 0, 其他不動.
>
> **clamp 這個字**: 木工用來把板子固定住的 C 型夾. 動詞 clamp = 夾緊、壓制; "The police clamped down on ..." = 強力取締. 意象是「從邊界外施力, 讓東西不能越界」.
>
> **為何這樣命名**: 圖學與數學函式庫慣用 `clamp(x, lo, hi)` (GLSL、C++17 `std::clamp` 等), Prometheus 沿用此慣例並拆成 `clamp_min` / `clamp_max` / `clamp` 三個函式. [出處 or 未查證]
>
> | 候選字 | 感覺 | 差異 |
> |---|---|---|
> | floor | 地板, 但在數學裡已專指「無條件捨去」 | 會撞名 |
> | limit | 抽象的「限制」 | 沒有「夾住邊界」的畫面 |
> | bound | 邊界, 偏名詞 | 常用於描述而非動作 |
>
> **陷阱**: `clamp_min` 不是「取最小」, 而是「設最小值」, 等價於 `max(v, min)`.
